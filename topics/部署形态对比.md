# 部署形态对比

> 验证环境:纯文档,无依赖;镜像体积为 2026-08 常见基线(仅供参考)。

**一句话:** Java 部署「JAR + JRE 镜像」,启动慢、内存大、要调优;Go 是「单个静态二进制 + scratch 镜像」,秒级启动、内存小;Python/Node/PHP 都带解释器/运行时镜像,但进程模型各不相同。

## 部署形态对照表

| 维度 | Java | Go | Python | Node.js | PHP |
|---|---|---|---|---|---|
| 构建产物 | JAR/WAR | 单个静态二进制 | 源码 + 依赖(venv 快照) | 源码 + node_modules | 源码 + vendor/ |
| 典型镜像 | eclipse-temurin JRE + JAR | distroless/scratch + 二进制 | python:3.13-slim + 依赖 | node:22-alpine + 依赖 | php:8.4-fpm + nginx |
| 镜像体积 | 200–400MB | **10–30MB** | 300–600MB | 300–500MB | 400–700MB |
| 启动时间 | 5–30s(JVM 预热) | **毫秒级** | 1–5s | 0.5–2s | 毫秒级(FPM) |
| 运行时内存 | 300MB–2GB+ | 10–100MB | 100–500MB | 100–500MB | 20–100MB/进程 |
| 进程模型 | 1 JVM = 1 进程,内建线程池 | 1 二进制 = 1 进程,goroutine 并发 | 多 worker(gunicorn/uvicorn) | 单进程 + cluster 模式 | FPM 进程池 + nginx |
| 优雅停机 | shutdown hook / actuator | signal.Notify + http.Server.Shutdown | worker 信号处理 | SIGTERM 处理 | FPM reload |
| 配置热更新 | 需重启/外部化配置 | 需重启(或 reload) | 需重启 | 需重启 | opcache reload |
| 水平扩展 | 无状态 + 外部会话 | 无状态天然 | 无状态 + 共享存储 | cluster/多实例 | FPM 多进程 + LB |

## 关键差异

### 1. Go 的「单二进制」哲学
- `go build` 产出静态二进制,无运行时依赖 → scratch/distroless 镜像,体积小、攻击面小、启动快。
- 心智转换:Java 部署要准备 JRE、处理 classpath、调 JVM 参数;Go 部署就是一个文件 + 环境变量。
- 云原生(K8s)场景:Go 二进制的资源占用和启动速度优势明显,这是它成为云原生首选语言的原因之一。

### 2. Java 的调优参数在别处没有对应物
- `-Xmx`、`-Xms`、`-XX:MaxMetaspaceSize`、GC 选择——其他语言没有这套东西。
- 对应物:Go 用 `GOMEMLIMIT`;Node 用 `--max-old-space-size`;Python/PHP 用容器 cgroup 限制即可。

### 3. Python 部署要「带环境」
- 源码不带依赖,部署要么构建期冻结 venv(poetry export / uv sync),要么在镜像构建时装依赖。
- 进程模型:gunicorn(多进程)或 uvicorn(ASGI),worker 数 = CPU × 2+1(经典公式)。

### 4. Node.js 的进程管理
- 单进程:PM2(守护/集群)/ systemd / K8s 多副本。
- cluster 模式:利用多核,但共享状态要外部化(Redis)。
- 心智转换:Java 的 JVM 内线程池 → Node 的多实例 + 外部存储。

### 5. PHP 的 FPM + nginx 组合
- 静态文件 nginx 直接服务,动态请求转发 FPM;调优核心是 `pm.max_children`(≈ 内存上限 ÷ 单进程内存)。
- 传统部署最简(lnmp 一键脚本),容器化也成熟(php-fpm + nginx 双容器)。

## CI/CD 对照

| 环节 | Java | Go | Python | Node | PHP |
|---|---|---|---|---|---|
| 依赖安装 | mvn/gradle 依赖解析 | go mod download | pip install / uv sync | npm ci | composer install --no-dev |
| 测试 | mvn test | go test ./... | pytest | npm test | phpunit |
| 构建 | mvn package | go build | (无) | npm run build | (无) |
| 产物 | JAR → 镜像 | 二进制 → 镜像 | 依赖 → 镜像 | bundle → 镜像 | vendor → 镜像 |
| 质量门禁 | checkstyle/spotbugs | go vet + staticcheck | ruff + mypy | eslint + tsc | phpstan |

## 常见误区

- ❌ 拿 JVM 调优思维到处找「GC 参数」:Go/Node 只设内存上限,其余交给运行时。
- ❌ Go 镜像里装基础镜像图省事:scratch/distroless 更小更安全,静态二进制不需要 shell。
- ❌ Python 部署把 venv 当 .m2 全局用:每环境一份,构建期冻结。
- ❌ PHP 容器单进程跑 php-fpm 裸奔:必须有 nginx/网关 + 静态资源分离。
- ❌ Node 用 PM2 就能扛并发:多核要靠 cluster 或多实例,PM2 只是守护。
