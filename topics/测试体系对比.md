# 测试体系对比

> 验证环境:纯文档,无依赖;版本基线 JUnit 5 / Go 1.24 / Python 3.13 / Node 22 / PHP 8.4。

**一句话:** Java 测试靠「框架生态」(JUnit + Mockito + JaCoCo);Go 把测试内置进语言(`go test`);Python 用 pytest(事实标准);Node 用 Jest/Vitest;PHP 用 PHPUnit——概念一一对应,写法各不相同。

## 测试框架对照表

| 维度 | Java | Go | Python | Node.js | PHP |
|---|---|---|---|---|---|
| 框架 | JUnit 5 | go test(内置) | pytest | Jest / Vitest | PHPUnit |
| 测试发现 | 注解 @Test + 扫描 | 文件名 _test.go + TestXxx | test_*.py + 函数 | *.test.js 约定 | *Test.php 约定 |
| 断言 | Assertions.* | testing.T 方法 / testify | assert.* | expect().toBe() | assertSame 等 |
| 参数化 | @ParameterizedTest | table-driven(表驱动) | @pytest.mark.parametrize | test.each | @dataProvider |
| Mock | Mockito / MockMvc | 接口 + 手写 stub(testify/mock) | unittest.mock / pytest-mock | jest.mock / vi.mock | PHPUnit mock |
| 覆盖率 | JaCoCo | go test -cover | pytest-cov | --coverage | --coverage |
| 并行 | JUnit 5 并行 | t.Parallel(默认单测) | pytest-xdist | --maxWorkers | PHPUnit 并行(8.3+) |
| 测试替身 | mock/spy/桩 类型丰富 | 靠接口,手写 | 自动 mock 强大 | 自动 mock 强大 | 内置 mock 对象 |

## 关键差异

### 1. Go:测试是语言的一部分
- 无需框架:任何 `_test.go` 文件里的 `func TestXxx(t *testing.T)` 都是测试。
- **表驱动测试**是 Go 惯例:输入/期望数据表 + 一个循环,替代 Java 的 @ParameterizedTest。
- mock:Go 无反射式自动 mock(接口就是 mock 点),常用做法是定义小接口 + 手写 stub,或用 testify/mock 生成。

### 2. Python:pytest 的 fixture 体系
- fixture(夹具)替代 JUnit 的 @Before/@After 生命周期,按需注入。
- mock 极强:`unittest.mock` 可替换任意对象/方法(含第三方库),比 Mockito 更「暴力」。

### 3. Node.js:Jest 全家桶
- 自带断言 + mock + 覆盖率 + watch 模式,一个工具全包。
- 异步测试是核心:async 函数 + await,超时控制与 Java 不同(默认 5s)。
- 心智转换:Java 测试同步为主;Node 测试几乎都是异步的。

### 4. PHP:PHPUnit 与 JUnit 血缘最近
- 命名、断言、@dataProvider(≈@ParameterizedTest)、mock 用法几乎一一对应,Java 开发者上手最快。
- 心智转换:最小。

## 测试金字塔在四门语言中的对应实践

| 层 | Java | Go | Python | Node | PHP |
|---|---|---|---|---|---|
| 单元测试 | JUnit + Mockito | go test + 接口 stub | pytest + mock | Jest 单测 | PHPUnit |
| 集成测试 | Testcontainers / Spring Boot Test | 真实依赖 + docker | pytest-docker | jest + testcontainers | PHPUnit + 测试库 |
| 契约/API 测试 | REST Assured | httptest(内置) | requests + pytest | supertest | PHPUnit + Laravel Test |
| E2E | Selenium/Playwright | Playwright | Playwright | Playwright | Playwright |

## 常见误区

- ❌ 以为 Go 没测试框架:内置 + 表驱动是特色,不是缺失。
- ❌ Java 的「mock 一切」带到 Go:Go 社区更倾向「小接口 + 真实依赖」,过度 mock 反而不惯用。
- ❌ pytest 里手写 setup/teardown 类(Java 习惯):fixture 才是正道。
- ❌ Node 测试不处理异步:忘记 await 或 mock 异步函数,测试假绿。
- ❌ CI 里跑测试不带覆盖率门槛:各语言都支持 gate(JaCoCo check / go cover / pytest-cov fail_under)。
