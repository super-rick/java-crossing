# 并发模型对比

> 验证环境:纯文档,无依赖;版本基线 Go 1.24 / Python 3.13 / Node 22 / PHP 8.4。

**一句话:** Java 用「线程 + 共享内存 + 锁」对抗式并发,Go 用「goroutine + channel」协作式并发,Node.js 用「单线程事件循环」,Python 三套并存,PHP 传统靠多进程。

## 心智模型对比

| 维度 | Java | Go | Python | Node.js | PHP |
|---|---|---|---|---|---|
| 基本单位 | 线程(OS 线程,1MB 栈) | goroutine(用户态,KB 级栈,动态增长) | 线程 / 进程 / 协程 | 单线程 + 异步回调 | 进程(FPM) |
| 并发原语 | synchronized / Lock / volatile | channel / sync.Mutex / atomic | threading.Lock / asyncio 原语 | (单线程,少用锁) | 进程隔离(无共享内存) |
| 并发容器 | ConcurrentHashMap / CopyOnWriteArrayList | sync.Map / channel | queue.Queue | — | — |
| 线程池 | ThreadPoolExecutor / ForkJoinPool | 无池概念(goroutine 即用即起) | ThreadPoolExecutor | worker_threads 池(手动) | 进程池(FPM) |
| 异步编排 | CompletableFuture / 响应式 | channel + select | asyncio.Task / Future | Promise / async-await | Swoole 协程 / Fiber |
| 并行能力 | 真并行(多核线程) | 真并行(多核,GMP 调度) | 真并行(进程);线程受 GIL | 单线程内并发不并行 | 多进程真并行 |
| 心智关键词 | 共享内存 + 锁 | **不要通过共享内存通信,通过通信共享内存** | 三选一:IO 密集 asyncio / CPU 密集多进程 | 一切皆异步,别阻塞 | 请求级,无常驻共享 |

## 关键差异

### 1. 线程成本
- Java 一个线程 ≈ 1MB 栈 + 内核对象,万级线程就是上限,所以要线程池。
- Go goroutine 初始约 2KB,百万级 goroutine 是常态,不需要池。
- 结论:Java 的「池化思维」移植到 Go 是第一个要扔掉的包袱。

### 2. 协作方式
- Java:多个线程操作同一对象 → 加锁保证可见性/原子性 → 死锁/活锁/饥饿问题。
- Go:goroutine 通过 channel 传值,数据所有权随消息转移 → 天然少锁;Mutex 仍有,但使用面窄。
- Node.js:没有多线程竞争,靠「回调/事件」协作;问题转移到「异步时序」。
- 迁移建议:先把 Java 并发场景翻译成「谁产生数据、谁消费数据」,再选原语。

### 3. Python 的三套模型(最容易选错)
| 场景 | 用哪个 | 原因 |
|---|---|---|
| IO 密集(网络/DB) | asyncio | 单线程事件循环,开销最小 |
| CPU 密集 | multiprocessing | 绕开 GIL,多核并行 |
| 简单脚本/已有同步库 | threading | 同步写法,GIL 下 IO 也能并发 |

> ⚠️ Java 思维陷阱:Python 里无脑用 threading 处理 CPU 密集任务,会被 GIL 限死(单核 100%)。Java 的线程池思维 → Python 先分场景,再选模型。

### 4. 事件循环 vs 线程
- Node.js:JS 代码跑在单线程,`fs`/网络等重活交给 libuv 线程池(默认 4,`UV_THREADPOOL_SIZE` 可调),完成后回调。
- 心智转换:Java 写「同步阻塞调用」的地方,Node 写「异步 + await」;CPU 密集任务必须交给 worker_threads,否则卡死整个进程。

### 5. PHP 的特殊性
- 传统 PHP-FPM:每个请求一个进程,进程间无共享内存 → 并发问题天然被隔离,但也意味着无法跨请求复用连接/状态。
- Swoole / Hyperf:协程常驻,才需要面对 Java 式的并发问题(锁、连接池)。

## 选型建议

| 需求 | 建议 |
|---|---|
| IO 密集高并发网关/服务 | Go(goroutine 性价比最高)或 Node(异步事件循环) |
| CPU 密集(计算/图像/编解码) | Java 线程池、Go、Python 多进程均可;Node 需 worker_threads |
| 大量并发长连接(IM/推送) | Go / Node(epoll/kqueue 模型天然适配) |
| 传统 Web 快速迭代 | PHP 进程模型简单可靠(并发交给 FPM) |
| 跨语言迁移学习 | 先 Go 再 Node,把两种心智模型都建立起来 |

## 常见误区

- ❌ 用 Java 线程池思维写 Go:开 1000 个 goroutine 完全正常,池化反而引入复杂度。
- ❌ Python 线程处理 CPU 密集任务:GIL 下没有加速。
- ❌ Node 里做 CPU 密集同步计算:事件循环被阻塞,整个服务无响应。
- ❌ 以为 PHP 应用内「共享内存」:传统 FPM 下进程隔离,状态只能放外部存储(Redis/DB)。
