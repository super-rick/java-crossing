# 包管理与构建对比

> 验证环境:纯文档,无依赖;版本基线 Maven 3.9 / Gradle 8.x / Go 1.24 / Python 3.13 / Node 22 / PHP 8.4。

**一句话:** Java 用「坐标 + 中央仓库 + 构建生命周期」(Maven/Gradle);Go 用「模块 + 语义化版本 + 全量下载」(go mod);Python 用「虚拟环境 + PyPI」;Node 用「node_modules + 锁文件」;PHP 用「composer + Packagist」。

## 包管理对照表

| 维度 | Java | Go | Python | Node.js | PHP |
|---|---|---|---|---|---|
| 工具 | Maven / Gradle | go mod | pip / poetry / uv | npm / pnpm / yarn | composer |
| 仓库 | Maven Central | proxy.golang.org | PyPI | npmjs.org | Packagist |
| 依赖声明 | pom.xml / build.gradle | go.mod | pyproject.toml / requirements.txt | package.json | composer.json |
| 锁文件 | (Maven 无;Gradle 有 lock) | go.sum | poetry.lock / uv.lock | package-lock.json | composer.lock |
| 版本策略 | 坐标版本(SNAPSHOT/RELEASE) | 语义化版本 + 最小版本选择 | 语义化版本 | 语义化版本 + semver 范围 | 语义化版本 |
| 依赖目录 | ~/.m2(全局) | GOPATH 模块缓存(全局) | site-packages(每虚拟环境) | node_modules(每项目) | vendor/(每项目) |
| 传递依赖 | 支持(冲突要手动仲裁) | 支持(MVS 自动选最小) | 支持 | 支持(嵌套/扁平) | 支持 |
| 发布 | mvn deploy(私服 Nexus) | go mod publish(tag) | twine → PyPI | npm publish | composer publish |
| 私服方案 | Nexus / Artifactory | GOPROXY 私有代理 | devpi / 私有索引 | Verdaccio / npm 私服 | Satis / Packagist 私有 |

## 构建对照表

| 维度 | Java | Go | Python | Node.js | PHP |
|---|---|---|---|---|---|
| 构建产物 | JAR/WAR | 单个静态二进制 | 源码/whl 包 | 源码 + 打包器产物 | 源码 |
| 构建命令 | mvn package / gradle build | go build | (无统一;打包用 hatch/poetry) | npm run build | (无) |
| 编译步骤 | 编译 + 资源处理 + 打包 | 编译即打包 | 无编译(语法检查) | 转译/打包(TS/bundler) | 无编译 |
| 测试接入 | surefire/failsafe | go test | pytest | jest | phpunit |
| 运行依赖 | JRE(或镜像内嵌) | 无(静态链接) | 解释器 + 依赖 | Node + node_modules | PHP + vendor |

## 关键差异

### 1. Go:无「构建生命周期」概念
- Maven 的 compile→test→package→deploy 阶段模型,Go 里就是 `go build` / `go test` / `go vet`,一步到位。
- 依赖版本冲突:Java 要手动仲裁传递依赖,Go 用「最小版本选择(MVS)」自动解决,基本不冲突。

### 2. Python:虚拟环境是必需品
- Java 的依赖是「全局一个 .m2」;Python 不同项目依赖可能冲突,必须 venv 隔离。
- 心智转换:`.m2` → 每个项目一个 `venv`;部署时锁定 `requirements.txt` 或 `uv.lock`。

### 3. Node.js:node_modules 与锁文件
- 每项目一个 node_modules,体积大;必须提交 lock 文件保证可复现。
- 版本范围(`^1.2.3`)与锁文件配合:npm ci 按锁文件精确安装(CI 里别用 npm install)。

### 4. PHP:vendor 目录随项目
- composer install 生成 vendor/,目录随项目(类似 node_modules);生产部署需要 composer install --no-dev。

### 5. 国内网络(中国开发者附加项)
- Maven:阿里云镜像;Go:GOPROXY=https://goproxy.cn;Python:pip 清华镜像;Node:npm 淘宝镜像;PHP:Packagist 镜像。CI 里配置对应镜像可大幅提速。

## 选型建议

- 单体多模块:Java 的 Gradle 最强;Go 用多包 + workspace(1.18+)。
- 微服务多仓库:各语言工具独立,统一用 CI 流水线编排。
- 脚本/工具:Python + uv(现代、快)或 Go 单文件。

## 常见误区

- ❌ Go 项目塞 .m2 式「全局依赖目录」:模块缓存自动管理,别手动拷贝依赖。
- ❌ Python 直接 pip install 到全局:必须 venv/poetry/uv 隔离。
- ❌ CI 里用 npm install 代替 npm ci:不按锁文件,构建不可复现。
- ❌ 以为 PHP 部署要「编译」:PHP 无编译,composer install 即完成依赖。
