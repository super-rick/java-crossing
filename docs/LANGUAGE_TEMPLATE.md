# 语言内容模板(LANGUAGE_TEMPLATE)

> 验证环境:模板文档,无依赖。

每种语言目录 `languages/{lang}/` 必须严格包含以下 12 个文件。缺失、目录名不在允许列表、或模块文件缺少「验证环境」字段,将被 CI(`.github/scripts/check_structure.py`)拒绝。

## 目录结构

```
languages/{lang}/
├── README.md             # 语言索引:定位、验证环境、CI 基线版本、入口导航
├── 01-语言特性.md
├── 02-基础语法.md
├── 03-数据结构.md
├── 04-并发编程.md
├── 05-IO与网络.md
├── 06-测试.md
├── 07-生产框架.md
├── 08-部署运维.md
├── 09-监控.md
├── 10-常见误区.md
└── 11-学习路径.md
```

## 每个模块页面的强制格式

### 1. 头部(必须,CI 校验)

```markdown
> 锚点:Java 的 X 对应本语言的 Y
>
> 验证环境:语言版本 / OS / 依赖版本
```

「验证环境」字段缺失 → CI 失败。版本必须真实(示例代码实际跑过的环境)。

### 2. 主体:对照表驱动

- 核心内容是**对照表**:左列 Java,右列本语言。
- 表内代码片段必须可运行(可直接复制执行),并给出运行命令与期望输出。
- 相同点简短带过(「与 Java 一致」),不同点展开讲透。

### 3. Java 思维陷阱(每模块 ≥1 个)

```markdown
> ⚠️ Java 思维陷阱:XX 场景下,把 Java 的 Y 直接搬过来会踩 Z 坑。正确做法是……
```

### 4. 底部:权威链接

官方文档、官方 wiki、主流框架文档。禁止随意转载内容,链接到源头。

## 新增语言流程

1. 复制 `languages/go/` 整个目录(结构即模板)。
2. 逐模块替换内容:先 README.md 与 01,再 02–10(每篇保持锚点格式),最后 11。
3. `examples/` 新增 `<lang>-order-service`,并在 `.github/workflows/examples-test.yml` 矩阵加一行。
4. 更新根 `README.md` 语言覆盖表 + `docs/02-语言全景对比.md` 对应行。
5. 每模块完成后本地运行 `python .github/scripts/check_structure.py` 自检。

## 质量红线

- 不提交未运行过的示例代码(所有示例注明运行输出)。
- 版本号以 CI 锁定为准,不在文档中写死未经验证的版本。
- 对照表必须逐项对应,禁止「本语言有 XX」式单边介绍。
