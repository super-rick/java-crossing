# Python · 06 测试

> 锚点:Java 的 JUnit 5 + Mockito + JaCoCo 对应 Python 的 pytest + unittest.mock + coverage。
>
> 验证环境:Python 3.11.15 + pytest 8.x(实测输出)。

**一句话:pytest 是事实标准——fixture 替代 @Before/@After,参数化替代 @ParameterizedTest,mock 比 Mockito 更「暴力」(能替换任意对象)。**

## 测试对照表

| 维度 | Java | Python |
|---|---|---|
| 框架 | JUnit 5 | **pytest** |
| 测试发现 | @Test 注解 + 扫描 | `test_*.py` / `*_test.py` 文件 + `test_` 函数 |
| 断言 | Assertions.assertEquals | **assert 原生语句**(`assert x == y`) |
| 参数化 | @ParameterizedTest | `@pytest.mark.parametrize` |
| 生命周期 | @BeforeEach/@AfterEach | **fixture(按需注入,更灵活)** |
| Mock | Mockito | **unittest.mock**(可替换任意对象/属性) |
| 覆盖率 | JaCoCo | pytest-cov(或 coverage 工具) |
| 异常断言 | assertThrows | `pytest.raises(ValueError)` |
| 并行 | JUnit 5 并行 | pytest-xdist |

## 完整对照示例(实测)

被测代码 `calc.py`:

```python
def add(a, b):
    return a + b


def divide(a, b):
    if b == 0:
        raise ValueError("division by zero")
    return a / b
```

测试代码 `test_calc.py`:

```python
import pytest

from calc import add, divide


@pytest.mark.parametrize("a,b,expected", [(1, 2, 3), (0, 0, 0), (-1, 1, 0)])
def test_add(a, b, expected):
    assert add(a, b) == expected


def test_divide_normal():
    assert divide(10, 2) == 5


def test_divide_zero():
    with pytest.raises(ValueError):
        divide(1, 0)


@pytest.fixture
def numbers():
    return [1, 2, 3]


def test_fixture(numbers):
    assert sum(numbers) == 6
```

运行:`python -m pytest test_calc.py -v`
实测输出:


## 关键差异

### 1. fixture ≈ 生命周期 + 依赖注入

```python
@pytest.fixture
def db_conn():
    conn = create_conn()      # ≈ @BeforeEach
    yield conn                # 测试执行
    conn.close()              # ≈ @AfterEach(teardown)
```

- 比 JUnit 的 @BeforeEach 强大:fixture 可组合、可作用域(session/module/function)、按参数名自动注入。
- Java 的 @Before/@After 成对写法 → Python 的 yield fixture 一屏搞定。

### 2. mock:能替换「任何东西」

```python
from unittest.mock import patch

@patch("app.services.payment.charge")   # 替换任意模块的属性
def test_pay(mock_charge):
    mock_charge.return_value = {"ok": True}
    # 被测代码调用 charge 时拿到 mock 结果
```

- Mockito 只能 mock 接口/类;unittest.mock 能 patch 任何模块属性(含第三方库、内置函数)——更强,但更需自律(别 mock 过度)。

### 3. 断言即 assert

- 无断言库依赖,`assert x == y` 是 Python 语句;pytest 捕获 AssertionError 并展示差异。
- 失败信息:pytest 自动 diff 大对象,比 JUnit 的 assertEquals 报错更直观。

### 4. 覆盖率门槛

```bash
python -m pytest --cov=. --cov-fail-under=80
```

> ⚠️ Java 思维陷阱 1:写 test 类(TestXxx 类 + 方法)——pytest 用顶层函数即可,类(TestXxx)也可但要遵守命名;函数式更惯用。
>
> ⚠️ Java 思维陷阱 2:把测试放独立 src/test 目录——pytest 惯例测试与被测代码同目录或 tests/ 目录,靠文件/函数命名发现,无注解。
>
> ⚠️ Java 思维陷阱 3:过度 mock——pytest 生态同样倡导「真实依赖 + 少量 mock」;mock 一切会让测试失去意义。
