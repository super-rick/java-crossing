# Python · 04 并发编程(三套模型选型)

> 锚点:Java 的 Thread/线程池/CompletableFuture 对应 Python 的 threading/multiprocessing/asyncio 三套体系。
>
> 验证环境:Python 3.11.15(实测输出)。

**一句话:Java 一套并发模型(线程+锁+异步编排)打天下;Python 有三套——threading(受 GIL 限制)、multiprocessing(绕开 GIL)、asyncio(单线程协程),选错模型是 Python 并发最大的坑。**

## 并发原语对照表

| 概念 | Java | Python |
|---|---|---|
| 线程 | Thread | threading.Thread |
| 锁 | synchronized / Lock | threading.Lock(with 语句) |
| 线程池 | ThreadPoolExecutor(Java) | concurrent.futures.ThreadPoolExecutor(同名!) |
| 进程池 | (少见) | concurrent.futures.ProcessPoolExecutor |
| 等待完成 | join() / Future.get() | t.join() / future.result() |
| 异步编排 | CompletableFuture | asyncio.gather / asyncio.Task |
| 定时任务 | ScheduledExecutorService | asyncio.ensure_future + sleep / sched |
| 原子操作 | AtomicInteger | (GIL 下简单操作天然安全;复杂用锁) |
| 线程局部 | ThreadLocal | threading.local |

## 三套模型选型(核心决策表)

| 场景 | 用哪个 | 原因 |
|---|---|---|
| **IO 密集**(网络/DB/文件) | **asyncio** 或 threading | IO 等待时释放 GIL/事件循环,协程开销最小 |
| **CPU 密集**(计算/编解码) | **multiprocessing** | 绕开 GIL,真多核并行 |
| 同步库为主 + 简单并发 | threading | 写法同步,IO 场景也能并发 |
| 混合负载 | 分层:计算进程 + IO 协程 | 见下方实战 |

## 完整对照示例(实测)

```python
import asyncio
import threading

counter = 0
lock = threading.Lock()


def worker():
    global counter
    for _ in range(100):
        with lock:  # ≈ synchronized,with 自动释放
            counter += 1


def main():
    # 线程 + 锁(≈ Thread + synchronized)
    threads = [threading.Thread(target=worker) for _ in range(10)]
    for t in threads:
        t.start()
    for t in threads:
        t.join()  # ≈ thread.join()
    print("counter:", counter)  # 期望 1000

    # asyncio(异步编排,≈ CompletableFuture)
    async def fetch(name, delay):
        await asyncio.sleep(delay)
        return f"{name} done"

    async def main_async():
        results = await asyncio.gather(fetch("a", 0.1), fetch("b", 0.05))
        print("async:", results)  # ≈ CompletableFuture.allOf

    asyncio.run(main_async())


if __name__ == "__main__":
    main()
```

运行:`python main.py`
输出:

```
counter: 1000
async: ['a done', 'b done']
```

## 关键差异

### 1. GIL 到底是什么

- CPython 解释器同一时刻只执行一个线程的字节码。
- **IO 密集**:线程等待网络/磁盘时释放 GIL → 其他线程可执行 → 线程并发有效。
- **CPU 密集**:两个线程抢一个 GIL,交替执行 → 比单线程还慢(多了切换开销)→ 必须 multiprocessing。
- 判断口诀:**等(IO)用线程/协程,算(CPU)用进程**。

### 2. asyncio 心智(与 Java 异步的异同)

- 与 CompletableFuture 类似:单线程事件循环调度协程。
- 语法更简洁:`async def` + `await`(≈ Kotlin 协程/JS async-await,比 Java 的 thenApply 链可读)。
- **致命陷阱**:asyncio 里调用同步阻塞库(requests、标准库文件 IO)会**卡死整个事件循环**——必须用 `asyncio.to_thread` 或纯异步库(httpx、aiofiles)。

### 3. concurrent.futures 与 Java 同名同构

```python
from concurrent.futures import ThreadPoolExecutor

with ThreadPoolExecutor(max_workers=4) as pool:
    futures = [pool.submit(fetch_url, u) for u in urls]
    for f in futures:
        print(f.result())  # ≈ Future.get()
```

Java 开发者看到 `ThreadPoolExecutor`/`Future.get()` 几乎零成本迁移——但记住 CPU 密集要换 `ProcessPoolExecutor`。

> ⚠️ Java 思维陷阱 1:无脑 threading 处理 CPU 密集任务——GIL 下没有加速,反而更慢。**先判断 IO 还是 CPU,再选模型。**
>
> ⚠️ Java 思维陷阱 2:以为 asyncio 与 Java NIO 完全不同——事件循环概念同源,只是语法更简洁;真正的坑是「混用同步库」。
>
> ⚠️ Java 思维陷阱 3:忘记锁的自动释放——Python 的 `with lock:` 自动释放(≈ Java 的 try-with-resources 锁),但手写 `lock.acquire()/release()` 忘记 release 同样死锁;线程安全队列用 `queue.Queue` 免锁。

## 生产模式对照

| 场景 | Java | Python |
|---|---|---|
| 并发请求聚合 | CompletableFuture.allOf | asyncio.gather / ThreadPoolExecutor.map |
| 超时控制 | Future.get(timeout) | `asyncio.wait_for(coro, 3)` |
| 限流 | Guava RateLimiter | 无标准库;asyncio.Semaphore |
| 取消 | Future.cancel | task.cancel() |
| 信号量 | Semaphore | threading.Semaphore / asyncio.Semaphore |
