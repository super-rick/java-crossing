# Python · 10 常见误区(Java 思维移植的坑)

> 锚点:把 Java 的习惯直接搬进 Python 会踩的坑。
>
> 验证环境:纯文档,坑位来自前 09 个模块的实测与 Python 社区共识。

| # | 误区(Java 思维) | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 用 threading 处理 CPU 密集任务 | GIL 下无加速,甚至更慢 | 先判断 IO/CPU:IO 用 asyncio/threading,CPU 用 multiprocessing |
| 2 | 变量/参数不写类型注解 | 大项目可维护性崩塌,IDE 提示失效 | `def f(x: int) -> str:` + mypy/pyright |
| 3 | 写 getter/setter 三件套 | 代码膨胀,非 Pythonic | 属性直接访问;要逻辑用 @property |
| 4 | 找方法重载 | Python 无重载 | 默认参数 `def f(x, mode="a")` |
| 5 | 用 `new` / 分号 / 大括号 | 语法错误 | `User()`;缩进即语法 |
| 6 | 全局 pip install | 项目依赖互相污染 | **venv/uv 每项目隔离** |
| 7 | 不锁依赖版本 | 生产不可复现,更新炸了 | requirements.lock / uv.lock |
| 8 | 忘记关闭文件/资源 | 句柄泄漏 | `with open(...)` / `with lock:` |
| 9 | map.get 返回 null 判空 | KeyError | `m.get(k, default)` / `k in m` |
| 10 | 手写循环收集结果 | 代码冗长 | 列表推导 `[f(x) for x in items]` |
| 11 | asyncio 里调同步阻塞库 | **卡死整个事件循环** | httpx / asyncio.to_thread |
| 12 | 手写锁 acquire/release | 忘 release 死锁 | `with lock:` 自动释放 |
| 13 | 测试写 test 类 + 注解 | 多此一举 | pytest 顶层函数 + parametrize + fixture |
| 14 | 找 Spring 全家桶 | 找不到(生态不同) | FastAPI + SQLAlchemy + Alembic 组合 |
| 15 | 异常「吞掉」只打日志 | 错误静默,排查困难 | 显式 raise / 链式 `raise ... from e` |
| 16 | 用 `== None` 判断空值 | 语义不对(== 触发 __eq__) | `is None`(身份比较) |
| 17 | 字符串拼接做日志 | 参数在非日志级别也求值,性能浪费 | logging 的 `%s` 占位符惰性求值 |
| 18 | 以为 Python 没 GC | 引用计数即时释放,但循环引用/全局缓存会泄漏 | 长期持有 = 泄漏;tracemalloc 排查 |
| 19 | 裸 `except:` | 吞掉 KeyboardInterrupt 等所有异常 | `except Exception:` + 明确处理 |
| 20 | 大循环里逐行操作数据库 | 慢一个数量级 | 批量操作(bulk)/ 事务合并 |

## 总结

Python 的哲学是「**简单胜过复杂,显式胜过隐式**」。对 Java 开发者:动态类型要主动用注解补强,并发要按场景选模型,依赖要主动隔离锁定——这三件事做到,Python 的开发效率优势就完整拿到了。
