# Python · 07 生产框架

> 锚点:Java 的 Spring Boot + MyBatis + Bean Validation + springdoc 对应 Python 的 FastAPI/Django + SQLAlchemy + pydantic(自动校验+自动文档)。
>
> 验证环境:Python 3.11.15 + FastAPI 0.1xx + uvicorn(实测输出)。

**一句话:FastAPI 用「类型注解」同时解决三个问题——参数校验(pydantic)、自动文档(OpenAPI)、异步支持;Java 里 springdoc + Bean Validation 的组合,它开箱即得。**

## 框架对照表

| 维度 | Java | Python |
|---|---|---|
| API 框架 | Spring Boot(Spring MVC) | **FastAPI**(API 优先)/ Flask(极简) |
| 全栈框架 | (Spring 全家桶) | **Django**(Admin/ORM/模板内置) |
| 参数校验 | Bean Validation(@Valid) | **pydantic(类型注解即校验)** |
| OpenAPI 文档 | springdoc | **FastAPI 自动生成 /docs** |
| ORM | MyBatis / JPA | **SQLAlchemy** / Django ORM / Tortoise(异步) |
| 配置 | application.yml + @ConfigurationProperties | pydantic-settings / python-dotenv |
| 依赖注入 | Spring 容器 | FastAPI Depends(函数式 DI) |
| 异步 | WebFlux / @Async | 原生 async def 支持 |
| 迁移 | Flyway / Liquibase | Alembic(SQLAlchemy 配套) |

## 最小 FastAPI 服务(实测)

```python
from fastapi import FastAPI

app = FastAPI(title="order demo")


@app.get("/hello")
def hello(name: str = "world"):
    # 类型注解即校验:name 缺省 "world",自动生成 OpenAPI 文档
    return {"message": f"Hello, {name}"}
```

运行:`uvicorn app:app --port 18084`(或 `uv run --with fastapi --with uvicorn ...`)
请求 `GET /hello?name=go`,实测响应:

```json
{"message":"Hello, go"}
```

**自动文档**:`GET /openapi.json` 返回标准 OpenAPI 3.1(实测):

```json
{"openapi":"3.1.0","info":{"title":"order demo","version":"0.1.0"},
 "paths":{"/hello":{"get":{"summary":"Hello","parameters":[{"name":"name","in":"query",...}]}}}}
```

交互文档:`http://localhost:18084/docs`(Swagger UI,≈ springdoc 的 swagger-ui)。

## 关键差异

### 1. 类型注解 = 校验 = 文档(三合一)

```python
from pydantic import BaseModel

class CreateOrder(BaseModel):
    item: str                 # 必填字符串
    quantity: int = 1         # 默认值
    note: str | None = None   # 可空(3.10+ 语法)

@app.post("/orders")
def create_order(order: CreateOrder):
    # 自动:JSON 解析 + 类型校验 + 400 错误 + OpenAPI schema
    return {"item": order.item, "qty": order.quantity}
```

- Java:DTO + @NotNull 注解 + springdoc 插件 = 三套东西。
- Python:pydantic 一个模型搞定——这是 FastAPI 对 Java 开发者「效率冲击」最直观的地方。

### 2. 依赖注入:函数式

```python
def get_db():
    db = connect_db()
    try:
        yield db          # ≈ @Bean 作用域 + 生命周期
    finally:
        db.close()

@app.get("/orders/{oid}")
def get_order(oid: int, db=Depends(get_db)):
    return db.query(oid)  # 自动注入
```

- Spring 的注解注入 → FastAPI 的 `Depends()` 函数参数注入,概念对应但更直白。

### 3. Django:全家桶路线

| 能力 | Django | Spring 对应 |
|---|---|---|
| Admin 后台 | **内置,开箱即用** | (需搭 RuoYi 等) |
| ORM | Django ORM(自动迁移) | JPA |
| 模板 | 内置模板引擎 | Thymeleaf |
| 适合场景 | 内容型/管理型/快速全栈 | 企业业务系统 |

- 选型:**纯 API → FastAPI;带后台管理/全栈 → Django**。

### 4. SQLAlchemy ≈ JPA(但更贴近 SQL)

```python
from sqlalchemy import create_engine, Column, Integer, String
from sqlalchemy.orm import declarative_base, sessionmaker

Base = declarative_base()

class Order(Base):
    __tablename__ = "orders"
    id = Column(Integer, primary_key=True)
    item = Column(String, nullable=False)

engine = create_engine("sqlite:///orders.db")     # ≈ HikariCP 池(内置)
Session = sessionmaker(bind=engine)
```

> ⚠️ Java 思维陷阱 1:找 Spring 全家桶——Python 是「按需组合」:FastAPI + SQLAlchemy + Alembic + pydantic-settings 就是事实标准组合(与 Go 的组合文化类似,但比 Go 更「开箱」)。
>
> ⚠️ Java 思维陷阱 2:写 getter/setter——Python 属性直接访问(`order.item`),要逻辑用 `@property`;pydantic 模型同理。
>
> ⚠️ Java 思维陷阱 3:异步陷阱——FastAPI 的 `def` 端点跑在线程池,`async def` 跑在事件循环;**端点内部别混用**,同步库用 def,异步库用 async def。
