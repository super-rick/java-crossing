# Python · 08 部署运维

> 锚点:Java 的 JAR + JRE 镜像 + JVM 调优对应 Python 的解释器镜像 + venv 依赖 + gunicorn/uvicorn 进程模型。
>
> 验证环境:纯文档(部署实践);版本基线 Python 3.13(CI)/ 3.11(本地)。

**一句话:Python 没有编译产物——部署 = 解释器 + 依赖快照;进程模型是「多 worker 进程」(≈ JVM 内线程池的进程版)。**

## 部署形态对照表

| 维度 | Java | Python |
|---|---|---|
| 构建产物 | JAR/WAR | **无编译产物**(源码 + 依赖清单) |
| 依赖交付 | JAR 内含/镜像 | venv 冻结或镜像内 `pip install` |
| 典型镜像 | temurin JRE + JAR(200-400MB) | python:3.13-slim + 依赖(300-600MB) |
| 启动时间 | 5-30s | 1-5s |
| 进程模型 | 1 JVM 多线程 | **gunicorn/uvicorn 多 worker 进程** |
| 调优 | -Xmx/-XX:GC | 无 GC 调优;调 worker 数 + cgroup 内存 |
| 健康检查 | /actuator/health | 自建 /healthz |
| 配置 | application.yml + 环境 | 环境变量 + pydantic-settings |

## 生产部署流程

### 1. 依赖锁定(≈ 提交 pom.xml + lock)

```bash
python -m venv .venv            # 每项目隔离环境(必须)
pip install -r requirements.txt
pip freeze > requirements.lock  # 精确锁定版本(≈ Maven 的 lock/版本钉死)
# 现代方案:uv 一把梭(uv.lock 自动可复现)
```

### 2. 进程管理(≈ Tomcat 多线程的进程版)

```bash
# API 服务(FastAPI):uvicorn 单进程开发,生产用 gunicorn 多 worker
gunicorn app:app -w 4 -k uvicorn.workers.UvicornWorker -b 0.0.0.0:8080
# ≈ Tomcat 线程池:4 个 worker 进程,每个进程内异步处理
```

- worker 数经验:`2 × CPU + 1`(与 JVM 线程池公式不同,Python 进程模型按核数定)。
- 每个 worker 是独立进程(内存隔离),与 JVM 线程共享堆完全不同——**内存按 worker 数线性增长**。

### 3. 容器化

```dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY requirements.lock .
RUN pip install --no-cache-dir -r requirements.lock
COPY . .
EXPOSE 8080
CMD ["gunicorn", "app:app", "-w", "4", "-k", "uvicorn.workers.UvicornWorker", "-b", "0.0.0.0:8080"]
```

> ⚠️ Java 思维陷阱 1:全局 pip install——Python 依赖隔离是硬要求(不同项目依赖冲突是常态),**venv 是必需品**,类比:每个项目一个 .m2。
>
> ⚠️ Java 思维陷阱 2:不锁版本——`pip install flask` 每次装最新,生产可复现性靠 `requirements.lock`/`uv.lock`;Java 的 pom 版本钉死是默认,Python 要主动做。
>
> ⚠️ Java 思维陷阱 3:JVM 调优思维——Python 没有 -Xmx,内存靠 cgroup 限制 + worker 数控制;OOM 排查靠监控 RSS + tracemalloc。

## 常见部署形态

| 形态 | 命令/说明 |
|---|---|
| 开发 | `uvicorn app:app --reload`(热重载) |
| 生产(API) | gunicorn + UvicornWorker |
| 生产(异步原生) | `uvicorn --workers 4`(多进程模式) |
| 脚本/批处理 | cron + `python script.py`(或容器 CronJob) |
| 任务队列 | Celery worker 独立部署 |

## 配置管理

```python
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    db_url: str            # 从环境变量 DB_URL 读取
    port: int = 8080

settings = Settings()      # ≈ @ConfigurationProperties + 环境变量注入
```

- 容器/K8s 环境变量是标准配置通道(12-Factor),与 Java 的 -D 外部化配置同思路。
- 无 application.yml 热更新概念;配置变更 = 重启(或 K8s 滚动)。
