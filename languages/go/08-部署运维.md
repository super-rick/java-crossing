# Go · 08 部署运维

> 锚点:Java 的 JAR + JRE 镜像 + JVM 调优对应 Go 的单静态二进制 + scratch/distroless 镜像 + GOMEMLIMIT。
>
> 验证环境:Go 1.26.7 / Windows 11(git-bash),实测二进制 8.1MB(Windows 版;Linux 版通常 5–8MB)。

**一句话:Go 的部署是「一个文件」——编译出静态二进制,镜像只有它,秒级启动,内存占用是 JVM 的十分之一。**

## 部署形态对照表

| 维度 | Java | Go |
|---|---|---|
| 构建产物 | JAR/WAR(需 JRE) | **单个静态二进制**(零依赖) |
| 典型镜像 | eclipse-temurin JRE + JAR(200–400MB) | scratch/distroless + 二进制(**10–30MB**) |
| 启动时间 | 5–30s(JVM 预热) | **毫秒级** |
| 内存占用 | 300MB–2GB+ | 10–100MB |
| 运行依赖 | 需要 JRE/classpath | 无 |
| 进程模型 | 1 JVM 多线程 | 1 进程多 goroutine |
| 调优 | -Xmx/-XX:GC 参数 | GOMEMLIMIT(1.19+) |
| 优雅停机 | shutdown hook | signal.Notify + http.Server.Shutdown |
| 交叉编译 | 每平台一套工具链 | GOOS/GOARCH 一行搞定 |

## 实测:构建静态二进制

```bash
go build -o app .
ls -lh app
# 实测(Windows):8.1M app.exe
```

Linux 交叉编译:

```bash
# 一行交叉编译 Linux 版(≈ 无对应物,Java 做不到这么简单)
GOOS=linux GOARCH=amd64 go build -o app-linux .
```

## 容器化示例

```dockerfile
# 多阶段构建:构建镜像 → 运行镜像
FROM golang:1.26 AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -o app .

FROM scratch            # 或 gcr.io/distroless/static
COPY --from=builder /app/app /app
EXPOSE 8080
ENTRYPOINT ["/app"]
```

对比 Java 镜像:`FROM eclipse-temurin:21-jre` + 复制 JAR + 设 JVM 参数——Go 镜像没有 JRE,体积小一个数量级。

> ⚠️ Java 思维陷阱 1:JVM 调优文化移植——Go 运行时自动管理内存,唯一常用参数是 `GOMEMLIMIT`(容器里防 OOM):`GOMEMLIMIT=512MiB go run ./app`。官方态度:GOGC 默认值对绝大多数程序最优,别乱调。
>
> ⚠️ Java 思维陷阱 2:以为二进制不兼容平台——Go 二进制**绑定操作系统与架构**(Linux 版不能在 Windows 跑),交叉编译时 GOOS/GOARCH 必须正确。
>
> ⚠️ Java 思维陷阱 3:镜像里装 shell/基础工具——静态二进制 + scratch 镜像没有 shell,调试要用 `docker exec` 的替代方案(distroless 含 debug 变体)或依赖日志/pprof 排查。

## 生产运维要点

### 1. 优雅停机

```go
srv := &http.Server{Addr: ":8080"}
go srv.ListenAndServe()

quit := make(chan os.Signal, 1)
signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
<-quit
ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
srv.Shutdown(ctx) // ≈ Spring 的优雅停机 + 等待在途请求
```

### 2. 健康检查

```go
http.HandleFunc("/healthz", func(w http.ResponseWriter, r *http.Request) {
	w.WriteHeader(http.StatusOK)
	fmt.Fprintln(w, "ok")
})
// K8s liveness/readiness probe 指向它,≈ /actuator/health
```

### 3. 配置与发布

- 配置:环境变量/K8s ConfigMap(12-Factor),无 application.yml 热更新概念。
- 发布:镜像 tag + K8s rolling update;二进制替换 + 重启进程(无 classpath/依赖版本问题)。
- 回滚:镜像回滚到旧 tag 即完成(无「JAR 依赖不一致」类问题)。

## CI/CD 流水线(Go 服务)

```yaml
- run: go mod download && go vet ./... && go test ./... -cover
- run: GOOS=linux CGO_ENABLED=0 go build -o app .
- run: docker build -t registry/app:$TAG .
- run: docker push registry/app:$TAG
```
