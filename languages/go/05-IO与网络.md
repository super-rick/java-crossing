# Go · 05 IO 与网络

> 锚点:Java 的 java.io/NIO/Netty/Jackson 对应 Go 标准库的 os/io/net/http/encoding/json。
>
> 验证环境:Go 1.26.7 / Windows 11(git-bash),示例均为实测输出。

**一句话:Go 把网络 IO 的复杂性藏进了标准库——`net/http` 就是生产级服务器,不需要 Netty 那样的框架层;文件 IO 用 os 包一行读写。**

## IO 对照表

| 场景 | Java | Go |
|---|---|---|
| 读整个文件 | Files.readAllBytes(Path) | os.ReadFile(path) |
| 写整个文件 | Files.write(Path, bytes) | os.WriteFile(path, data, perm) |
| 流式读 | BufferedReader / InputStream | bufio.Scanner / io.Reader 接口 |
| 缓冲 | BufferedWriter | bufio.Writer |
| 序列化 | Jackson / Gson / protobuf | encoding/json / protobuf / msgpack |
| HTTP 客户端 | RestTemplate / HttpClient / OkHttp | net/http(标准库,Go 1.18+ 可设置请求超时) |
| HTTP 服务端 | Spring Boot(Tomcat/Netty) | net/http(标准库即可)/ gin |
| 异步网络 | Netty(Reactor 模式) | **不需要**:goroutine 阻塞式写法,底层 epoll |
| 错误处理 | IOException 异常体系 | 错误返回值 + os.IsNotExist 等判断 |

## 完整对照示例(实测)

### 1. 文件读写 + JSON 序列化

```go
package main

import (
	"encoding/json"
	"fmt"
	"os"
)

type User struct {
	Name string `json:"name"`
	Age  int    `json:"age"`
}

func main() {
	// 文件读写(≈ Files.readAllBytes / Files.write),相对当前目录
	const p = "godoc-data.txt"
	os.WriteFile(p, []byte("hello file"), 0644)
	b, _ := os.ReadFile(p)
	fmt.Println("file:", string(b))
	os.Remove(p)

	// JSON 序列化(≈ ObjectMapper.writeValueAsString)
	u := User{Name: "Alice", Age: 30}
	j, _ := json.Marshal(u)
	fmt.Println("json:", string(j))

	// 反序列化(≈ readValue)
	var u2 User
	json.Unmarshal(j, &u2)
	fmt.Println("unmarshal:", u2.Name, u2.Age)
}
```

运行:`go run main.go`
输出:

```
file: hello file
json: {"name":"Alice","age":30}
unmarshal: Alice 30
```

要点:
- struct tag `json:"name"` ≈ Jackson 的 `@JsonProperty` / `@JsonNaming`。
- 字段名大写才能导出(序列化可见),小写字段不参与。

### 2. HTTP 服务端(标准库)

```go
package main

import (
	"fmt"
	"net/http"
)

func main() {
	http.HandleFunc("/hello", func(w http.ResponseWriter, r *http.Request) {
		name := r.URL.Query().Get("name")
		fmt.Fprintf(w, "Hello, %s!", name)
	})
	http.ListenAndServe(":18080", nil)
}
```

运行:`go run main.go`,然后 `curl "http://localhost:18080/hello?name=go"`
输出:

```
Hello, go!
```

> ⚠️ Java 思维陷阱 1:以为标准库 http 是玩具——`net/http` 的并发模型(每个连接一个 goroutine)让**标准库就是生产级**,Spring Boot 的嵌入式 Tomcat 在 Go 里没有对应需求;要路由/中间件再上 Gin。
>
> ⚠️ Java 思维陷阱 2:同步阻塞写法担心性能——Go 的「阻塞式写法」底层是 epoll 多路复用 + goroutine 调度,写法同步、性能异步,别试图找 Netty 式异步 API。
>
> ⚠️ Java 思维陷阱 3:`os.ReadFile` 一次性读大文件——大文件要用流式(bufio.Scanner / io.Copy),和 Java 的 Files.readAllBytes 同样有内存上限问题。

## 网络编程心智对照

| 问题 | Java | Go |
|---|---|---|
| 高并发连接 | Netty / 虚拟线程(21+) | net/http 每个连接一个 goroutine |
| 超时控制 | HttpClient connectTimeout | http.Client{Timeout} + context |
| 取消/中断 | Future.cancel | context.Context 传递取消 |
| TCP 服务 | ServerSocket / Netty | net.Listen + goroutine per conn |
| 反向代理 | (Nginx 或框架) | httputil.ReverseProxy |
