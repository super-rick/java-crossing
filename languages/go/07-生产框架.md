# Go · 07 生产框架

> 锚点:Java 的 Spring Boot + MyBatis + Logback + application.yml 对应 Go 的 Gin/GORM + slog/zap + viper/env。
>
> 验证环境:Go 1.26.7 / Windows 11(git-bash),gin v1.11.x,示例均为实测输出。

**一句话:Go 没有 Spring 式全家桶——Web(Gin)+ ORM(GORM)+ 配置(viper)+ 日志(slog)自由组合,组合后是高度趋同的惯用栈。**

## 生态对照表

| 需求 | Java | Go 主流选择 |
|---|---|---|
| Web 框架 | Spring Boot / Spring MVC | **Gin**(最流行)/ Echo / Fiber / 标准库 |
| ORM | MyBatis / JPA | **GORM** / sqlx(原生 SQL) |
| 配置 | application.yml + @ConfigurationProperties | **viper**(文件+环境变量)或标准库 os.Getenv |
| 日志 | SLF4J + Logback | **log/slog**(标准库,1.21+)/ zap(高性能) |
| 参数校验 | Bean Validation | go-playground/validator |
| OpenAPI | springdoc | swaggo/swag(注释生成) |
| 连接池 | HikariCP | database/sql 内置连接池 |
| 迁移 | Flyway / Liquibase | golang-migrate / goose |
| 消息 | 各客户端 | 各客户端(官方 SDK 一般很全) |
| 依赖注入 | Spring 容器 | 手动 / wire / fx(Go 社区无强需求) |

## 最小 Gin 服务(实测)

```go
package main

import (
	"net/http"

	"github.com/gin-gonic/gin"
)

func main() {
	r := gin.Default()
	r.GET("/hello", func(c *gin.Context) {
		name := c.DefaultQuery("name", "world")
		c.JSON(http.StatusOK, gin.H{"message": "Hello, " + name})
	})
	r.Run(":18081")
}
```

运行:`go run main.go`(需先 `go get github.com/gin-gonic/gin`)
请求:`curl "http://localhost:18081/hello?name=go"`
实测响应:

```json
{"message":"Hello, go"}
```

对应关系:`r.GET("/hello", handler)` ≈ `@GetMapping("/hello")`;`c.JSON` ≈ `ResponseEntity` / `@ResponseBody`;`gin.Default()` ≈ Spring Boot 自动配置(自带 Logger + Recovery 中间件)。

## 生产要点

### 1. 配置:环境变量优先(12-Factor)

```go
// ≈ @Value("${server.port}")
port := os.Getenv("PORT")
if port == "" {
	port = "8080" // 默认值
}
```

- 简单服务直接 os.Getenv;复杂配置用 viper(YAML + 环境变量 + 热加载)。
- 容器化部署时**环境变量是标准配置通道**(和 Java 的 -D 或外部化配置一个思路)。

### 2. 日志:标准库 slog(1.21+)

```go
import "log/slog"

slog.Info("order created", "orderId", 12345, "amount", 99.5)
// ≈ log.info("order created orderId={} amount={}", 12345, 99.5)
```

- slog 输出结构化 JSON(生产用 `slog.NewJSONHandler`),与 Java 的 JSON 日志对齐。
- 需要高性能/更丰富功能用 zap(Go 的 Logback 对位)。

### 3. 数据库:GORM ≈ JPA,sqlx ≈ MyBatis

| 场景 | Java | Go |
|---|---|---|
| 全自动 ORM | JPA + Hibernate | GORM(自动迁移、关联、钩子) |
| 手写 SQL 可控 | MyBatis | sqlx / sqlc(SQL 生成类型安全代码) |

> ⚠️ Java 思维陷阱 1:找 Spring 全家桶——Go 是「组合文化」,Gin + GORM + viper + slog 就是事实上的「全家桶」,但没有统一框架父类;DI 容器非必需,构造函数注入是惯例。
>
> ⚠️ Java 思维陷阱 2:注解思维——Go 没有运行时注解,配置靠结构体 tag(`json:"..."`、`gorm:"..."`、`binding:"required"`)与显式代码。
>
> ⚠️ Java 思维陷阱 3:错误处理在框架层「兜底」——Gin 的 handler 出错要显式 `c.AbortWithStatusJSON(500, ...)`,没有 Spring 的全局 @ExceptionHandler 魔法(可自建中间件实现,但默认没有)。

## 微服务生态对应

| 需求 | Java | Go |
|---|---|---|
| 服务发现/注册 | Nacos / Eureka | 云原生:直接 K8s 或 etcd/consul 客户端 |
| RPC | Dubbo / gRPC | gRPC(官方支持最好)/ go-zero 微服务套件 |
| 网关 | Spring Cloud Gateway | K8s Ingress / Envoy / go-zero 网关 |
| 任务调度 | XXL-Job / Quartz | cron 库 + 容器调度(K8s CronJob) |
| 配置中心 | Nacos / Apollo | viper + 环境变量(K8s ConfigMap) |
