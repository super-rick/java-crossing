# Go · 09 监控

> 锚点:Java 的 Actuator + Micrometer + JFR/jstack 对应 Go 的 prometheus/client_golang + pprof + runtime/metrics。
>
> 验证环境:Go 1.26.7 / Windows 11(git-bash),示例均为实测输出。

**一句话:Java 的监控「开箱即得」(Actuator),Go 的监控「要自己接 5 行代码」——但 pprof 的性能剖析能力是内置的,比 JFR 接入简单一个数量级。**

## 监控对照表

| 维度 | Java | Go |
|---|---|---|
| 指标暴露 | Actuator /actuator/metrics(自动) | prometheus/client_golang 手动注册 /metrics |
| 运行时指标 | JVM 内存/GC/线程(开箱) | runtime/metrics(GC/goroutine/内存,需自接) |
| 健康检查 | /actuator/health | 自建 /healthz |
| 日志 | SLF4J + Logback | log/slog(结构化)/ zap |
| 性能剖析 | JFR / jstack / MAT | **pprof(内置,标准库 import 即用)** |
| 线上诊断 | Arthas | pprof + delve |
| 链路追踪 | Micrometer Tracing + OTel | OpenTelemetry Go SDK |
| 告警 | 平台级 | Prometheus Alertmanager(通用) |

## pprof:内置剖析器(实测)

```go
package main

import (
	"fmt"
	"net/http"
	_ "net/http/pprof" // 空导入即可挂载 /debug/pprof/*
)

func main() {
	fmt.Println("pprof on :18082")
	http.ListenAndServe(":18082", nil)
}
```

运行:`go run main.go`
请求:`curl "http://localhost:18082/debug/pprof/goroutine?debug=1"`
实测输出(节选):

```
goroutine profile: total 3
1 @ 0x7ff767d57b9c ...
#	0x7ff767e02838	internal/poll.(*FD).pin+0x38	.../fd_windows.go:260
#	0x7ff767e6b3c4	net.(*netFD).Read+0x24	.../fd_posix.go:68
#	0x7ff767f52ef2	net/http.(*connReader).backgroundRead+0x32 .../server.go:702
```

关键端点(≈ jstack/jmap/JFR 的线上等价物):

| 端点 | 对应物 | 用途 |
|---|---|---|
| /debug/pprof/goroutine | jstack / thread dump | 看 goroutine 栈,找死锁/泄漏 |
| /debug/pprof/heap | jmap -dump / MAT | 内存剖析 |
| /debug/pprof/profile | JFR CPU 采样 | CPU 火焰图(30s 采样) |
| /debug/pprof/block | — | 阻塞分析 |

火焰图:

```bash
# 采集 30s CPU 剖析(≈ JFR 录制)
go tool pprof -http=:9090 http://localhost:18082/debug/pprof/profile?seconds=30
```

> ⚠️ Java 思维陷阱 1:等框架送监控——Go 没有 Actuator,`prometheus/client_golang` 注册一个 /metrics handler 就 5 行代码,但**必须自己写**;健康检查 /healthz 同理。这是 Go 的「显式」哲学:监控是你的事,不是框架的事。
>
> ⚠️ Java 思维陷阱 2:线上问题靠重启——Go 的 pprof 可以**对运行中的进程**采样,无需重启、无需 Agent;先 `curl .../debug/pprof/goroutine?debug=1` 看栈,再决定是否 dump。

## 指标接入(最小 Prometheus)

```go
import "github.com/prometheus/client_golang/prometheus/promhttp"

// 在路由上挂 /metrics
http.Handle("/metrics", promhttp.Handler())
```

然后 Grafana + Prometheus 采集,规则与 Java 服务完全一致——**跨语言统一监控栈**(见 topics/监控体系对比.md)。

## 日志规范

```go
// 结构化 JSON 日志(≈ Logback 的 JSON encoder)
logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
slog.SetDefault(logger)
slog.Info("order paid", "orderId", 1001, "costMs", 12)
// 输出: {"time":"...","level":"INFO","msg":"order paid","orderId":1001,"costMs":12}
```

统一 stdout + JSON → Loki/采集器,与 Java 服务的日志管线一致。
