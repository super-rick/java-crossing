# PHP · 07 生产框架

> 锚点:Java 的 Spring Boot + MyBatis + Bean Validation 对应 PHP 的 Laravel + Eloquent + Form Request Validation。
>
> 验证环境:PHP 8.4.24;Laravel 12 / Slim 4 / Hyperf 3(2026-08 稳定版)。

**一句话:PHP 框架分两派——Laravel 全家桶(≈ Spring Boot 的体验,Java 开发者最亲切)与 Slim(微框架);高并发场景用 Hyperf(协程)。**

## 框架对照表

| 维度 | Java | Laravel | Slim 4 | Hyperf |
|---|---|---|---|---|
| 定位 | 全家桶 | **全家桶**(生态最全) | 微框架(路由+中间件) | 协程高并发 |
| 依赖注入 | Spring 容器 | **容器 + 门面(Facade)** | 手动 | 注解 DI |
| 路由 | @RequestMapping | 路由文件 + 注解(11+) | 链式注册 | 注解路由 |
| ORM | MyBatis / JPA | **Eloquent**(ActiveRecord ≈ JPA) | 自选(Doctrine) | Eloquent/DB |
| 校验 | Bean Validation | **Form Request Validation**(内置) | 手动 | 注解校验 |
| 模板 | Thymeleaf | **Blade**(内置) | 无(API 用) | 无 |
| Admin | 需搭 | 生态(后台生成器多) | 无 | 无 |
| 并发模型 | 常驻线程 | FPM 进程 | FPM 进程 | **Swoole 协程常驻** |
| 迁移成本(Java) | — | **低(概念对齐)** | 低 | 中(协程心智) |

## 最小 Slim 4 服务(API 优先)

```php
<?php
use Psr\Http\Message\ResponseInterface as Response;
use Psr\Http\Message\ServerRequestInterface as Request;
use Slim\Factory\AppFactory;

require __DIR__ . '/../vendor/autoload.php';

$app = AppFactory::create();

$app->get('/hello', function (Request $request, Response $response) {
    $name = $request->getQueryParams()['name'] ?? 'world';
    $response->getBody()->write(json_encode(['message' => "Hello, $name"]));
    return $response->withHeader('Content-Type', 'application/json');
});

$app->run();
```

对应关系:`$app->get(path, handler)` ≈ `@GetMapping`;`$request->getQueryParams()` ≈ `@RequestParam`;JSON 手动序列化(无自动转换,可用中间件补)。

## Laravel ≈ Spring Boot 对照

| Spring Boot | Laravel |
|---|---|
| @RestController | 控制器类 + 路由 |
| @Autowired | 容器解析(构造函数注入) |
| application.yml | .env + config/ |
| Spring Data JPA | Eloquent ORM |
| Bean Validation | Form Request |
| Spring Security | Sanctum/Passport |
| Flyway | Migrations + Seeder |
| Lombok | (PHP 无,属性直接访问) |

```php
// Eloquent ≈ JPA Active Record
class Order extends Model {
    protected $fillable = ['item', 'quantity', 'paid'];
}

// ≈ orderRepository.save(order)
$order = Order::create(['item' => 'coffee', 'quantity' => 2]);
```

## Hyperf:协程高并发 PHP

- 基于 Swoole:常驻内存 + 协程 + 连接池 → 高并发能力接近 Go/Java。
- 心智:回到「常驻应用」模型(01 模块的 Java 思维重新适用:连接池、缓存、锁)。
- 适合:传统 PHP 团队的升级路径(不换语言栈拿并发能力)。

> ⚠️ Java 思维陷阱 1:找 Spring 全家桶的「自动配置魔法」——Laravel 最接近(Sail/artisan 命令体系),但 FPM 模型下没有常驻容器,每个请求重新引导框架(有 OPcache 加速)。
>
> ⚠️ Java 思维陷阱 2:异步/响应式思维——传统 PHP 无异步 API;并发请求外部服务是**串行**的,要么用 Swoole 协程,要么依赖消息队列异步化(架构层解决)。
>
> ⚠️ Java 思维陷阱 3:强类型校验依赖——Laravel 的 Form Request 校验是「运行时校验」(≈ Bean Validation 的运行时),PHP 的静态检查靠 PHPStan/Psalm(编译期没有)。

## 微服务生态对应

| 需求 | Java | PHP |
|---|---|---|
| 任务调度 | XXL-Job/Quartz | Laravel Scheduler(artisan schedule) |
| 消息 | Kafka 客户端 | 各客户端(phpkafka/AMQP) |
| 缓存 | Redis 客户端 | predis / PhpRedis |
| RPC | gRPC | gRPC 扩展 / Hyperf RPC |
| 网关 | Spring Cloud Gateway | nginx(事实上网关) |
