# PHP · 10 常见误区(Java 思维移植的坑)

> 锚点:把 Java 的习惯直接搬进 PHP 会踩的坑。
>
> 验证环境:纯文档,坑位来自前 09 个模块的实测与 PHP 社区共识。

| # | 误区(Java 思维) | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 用 static/内存缓存做跨请求共享 | **进程隔离,static 只活一个请求** | 共享状态放 Redis/DB |
| 2 | 按 JVM 线程池思维调并发 | 进程数受内存约束,不是并发需求 | pm.max_children = 内存 ÷ 单进程峰值 |
| 3 | 找 synchronized/并发容器 | 进程隔离无共享,无需锁 | 外部资源并发用事务/锁指令 |
| 4 | 弱类型裸奔 | `"2" + 1` 静默转换,线上数据错乱 | `declare(strict_types=1)` + 类型声明 + PHPStan |
| 5 | 忘记 $ 前缀 | 语法错误 | 所有变量/属性必须 `$` |
| 6 | 字符串用 `+` 拼接 | `"a" + "b"` 得 0(类型转换!) | `.` 拼接 / `"{$a}{$b}"` |
| 7 | `$map["missing"]` 直接读 | undefined key 报错 | `?? "default"` / array_key_exists |
| 8 | assertEquals 断言 | 弱类型比较(1 == "1")放行 | **assertSame** |
| 9 | 以为 json_decode 返回对象 | 不加 true 是 stdClass,加 true 是数组 | 统一约定 + 文档注明 |
| 10 | 异步/响应式思维 | 传统 PHP 无异步,并发是串行 | 消息队列异步化 / Swoole 协程 |
| 11 | 生产不开 OPcache | 性能差 3-5 倍 | opcache.enable=1 + 发布后 reset |
| 12 | 调优找 -Xmx | PHP 无堆参数 | memory_limit(单请求)+ FPM 参数 |
| 13 | 应用内计数器做监控 | 请求结束进程销毁,计数丢失 | 外部存储 / APM / 日志聚合 |
| 14 | 期望常驻服务/守护进程 | FPM 自带进程管理,无需应用守护 | php-fpm reload 秒级发布 |
| 15 | 忽略 nginx 层 | 静态资源/HTTPS/缓冲都在应用层做 | nginx 前置,应用只处理动态 |
| 16 | 手写 SQL 拼参数 | SQL 注入(历史教训) | PDO 预处理 / Eloquent |
| 17 | 全用文件存 session | 分布式后 session 不同步 | Redis session 存储 |
| 18 | 认为 PHP 不能高并发 | 传统 FPM 有限,但 Swoole/Hyperf 可协程化 | 场景匹配:传统 Web 用 FPM,高并发用 Hyperf |
| 19 | 忽略 composer.lock | 依赖浮动不可复现 | composer.lock 提交 + composer install --no-dev |
| 20 | PHP 8 还用旧语法 | 错过构造器提升/enum/readonly | 用 8.x 新特性 + PHPStan 把关 |

## 总结

PHP 的哲学是「**为 Web 请求而生**」:请求级生命周期让部署极简、天然免泄漏,但也决定了「无常驻状态、进程隔离、串行执行」。Java 开发者移植时最关键的转变:**放弃常驻内存假设**——状态外部化(Redis/DB)、并发靠进程数或 Swoole、监控靠 FPM 状态页 + 外部指标。接受这个模型,PHP 的运维简单性和传统 Web 场景的生产力优势就完全体现了。
