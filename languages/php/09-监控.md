# PHP · 09 监控

> 锚点:Java 的 Actuator + Micrometer + JFR 对应 PHP 的 FPM 状态页 + prometheus PHP 客户端 + Xdebug profiler。
>
> 验证环境:纯文档;版本基线 PHP 8.4 + Prometheus 生态。

**一句话:PHP 监控的「免费午餐」是 FPM 状态页(进程池健康度),应用指标自己接(prometheus 客户端),性能剖析用 Xdebug/Blackfire。**

## 监控对照表

| 维度 | Java | PHP |
|---|---|---|
| 进程池指标 | (JVM 线程) | **FPM status 页面**(内置!) |
| 应用指标 | Actuator/Micrometer | prometheus/client 库 / 第三方包 |
| 健康检查 | /actuator/health | 自建 /healthz |
| 日志 | SLF4J + Logback | **Monolog**(事实标准) |
| 性能剖析 | JFR / jstack | **Xdebug profiler** / Blackfire / Tideways |
| 慢查询 | 平台级 | **slow log(php-fpm 自带)** |
| 错误追踪 | APM | Sentry(官方 SDK 极成熟) |
| 链路追踪 | OTel | OpenTelemetry PHP SDK / SkyWalking agent |

## FPM 状态页(内置,≈ 免费的基础监控)

```ini
# php-fpm.conf 或 pool 配置
pm.status_path = /status
```

```nginx
# nginx 里放行
location = /status {
    fastcgi_pass unix:/run/php/php8.4-fpm.sock;
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
}
```

访问 `/status?full` 得到:

```
pool:                 www
process manager:      dynamic
start time:           22/Aug/2026:10:30:00 +0800
accepted conn:        12345
listen queue:         0          # 排队请求数!>0 = 进程池饱和
max listen queue:     3
max children reached: 2          # 触顶次数
slow requests:        0          # 慢请求数
```

**关键指标**:`listen queue`(排队数)与 `max children reached`(触顶)——等价于 Java 的线程池活跃/队列指标,是 FPM 调优的第一手数据。

> ⚠️ Java 思维陷阱 1:等应用框架送监控——PHP 框架无 Actuator;但 FPM status 是内置的(≈ Tomcat 的管理端点),先看它,再看应用指标。
>
> ⚠️ Java 思维陷阱 2:JFR/jstack 思维——PHP 无线程 dump(进程隔离);对位工具:Xdebug profiler(≈ JFR 录制)、php-fpm slow log(≈ 慢日志)。

## 应用指标(Prometheus)

```php
// 极简计数器(完整版用 promphp/prometheus_client_php)
$metrics = [];
$_POST['/orders'] = ($_POST['/orders'] ?? 0) + 1; // 示意;生产用专用库

header('Content-Type: text/plain');
echo "orders_total " . ($_POST['/orders'] ?? 0) . "\n";
```

- 完整方案:`promphp/prometheus_client_php` + FPM 状态页 + nginx 日志 → Prometheus + Grafana。
- **注意**:传统 FPM 每请求进程重建,内存计数器会丢失——**指标要么写外部存储,要么用 APM/日志聚合**,这是 PHP 监控与常驻语言的本质区别。

## 慢日志(内置,排查利器)

```ini
slowlog = /var/log/php-fpm-slow.log
request_slowlog_timeout = 5s   # 超过 5s 的请求记录调用栈
```

等价物:Java 的慢 SQL/慢接口日志,但 PHP 的 slow log 自带调用栈(≈ 微型的线上 profiler)。

## 日志规范(Monolog)

```php
use Monolog\Logger;
use Monolog\Handler\StreamHandler;

$log = new Logger('app');
$log->pushHandler(new StreamHandler('php://stdout', Logger::INFO)); // 统一 stdout

$log->info('order created', ['orderId' => 1001]); // 结构化上下文
```

- 统一 stdout + 采集器(Loki/ELK),与 Java 管线一致;Sentry 直接接 Monolog 处理器。

## 统一监控栈建议

```
PHP-FPM → FPM status + nginx access log + Monolog(stdout)+ APM(Sentry)
      ↓
  Prometheus / Loki / 平台 APM
      ↓
   Grafana 统一面板
```
