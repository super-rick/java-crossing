# PHP · 01 语言特性

> 锚点:Java 的「常驻 JVM + 多线程 + 强类型」对应 PHP 的「请求级进程 + 多进程 FPM + 动态弱类型」。
>
> 验证环境:PHP 8.4.24(实测输出)。

## 范式对比

| 维度 | Java | PHP |
|---|---|---|
| 生命周期 | **常驻 JVM**(应用级状态共享) | **请求级进程**(请求结束一切销毁) |
| 并发模型 | 线程 + 锁 | **多进程隔离**(传统)/ Swoole 协程(进阶) |
| 类型系统 | 静态强类型 | **动态弱类型**(PHP 8 可加强类型声明) |
| 执行方式 | 编译 → 字节码 → JIT | 解释执行(PHP 8 含 JIT,CLI/OPcache) |
| 内存管理 | 分代 GC | **引用计数 + 请求结束整块回收** |
| OO | 类继承 + 接口 + 泛型 | 类继承 + 接口 + trait(PHP 5.4+/8 完善) |
| 部署 | JAR + 守护进程 | **源码 + FPM 进程池 + nginx** |
| 生态 | 企业全家桶 | 传统 Web 统治 + Laravel 现代生态 |

## 关键差异

### 1. 请求级生命周期(最重要的心智模型)

```
请求到达 → FPM 分配一个进程 → 执行脚本 → 输出响应 → 进程状态清零
```

- **没有常驻内存**:应用内静态变量/缓存/连接在请求结束后全部销毁。
- Java:`static` 字段、内存缓存、连接池跨请求共享;PHP 传统模式**每次请求从零开始**。
- 推论:
  - 无内存泄漏问题(请求结束自动回收)→ 但也无跨请求复用。
  - 连接池/缓存要依赖外部(Redis/MySQL 连接由 FPM 的持久连接机制管理)。
  - **Java 的「常驻内存思维」在 PHP 传统模式完全不适用**。

实测(进程隔离):

```php
$GLOBALS['counter'] = ($GLOBALS['counter'] ?? 0) + 1;
echo "请求内 counter: " . $GLOBALS['counter'] . "\n";
echo "PID: " . getmypid() . "\n"; // 每次请求(进程)不同
```

运行:`php lang.php`
输出:

```
请求内 counter: 1
PID: 44924
说明:PHP-FPM 下每个请求独立进程,状态不跨请求保留
```

> ⚠️ Java 思维陷阱:用 static/内存缓存做跨请求共享——传统 FPM 下每个请求独立进程,static 只对本请求有效;共享状态必须放 Redis/DB。

### 2. 动态弱类型

```php
$x = 1;
$x = "now a string";   // 合法
echo 1 + "2";           // 3!字符串自动转数字(弱类型)
```

- 比 Python 更「弱」:`"2"` 参与算术自动转 int,不报错。
- PHP 8 提供严格模式:`declare(strict_types=1);` + 参数/返回类型声明,可接近 Java 的强类型体验。
- 心智转换:小脚本弱类型极快;生产系统用 **strict_types + PHPStan/Psalm** 找回类型安全。

### 3. 内存管理:引用计数 + 请求级回收

- 对象引用归零即释放(同 Python)。
- 传统模式:请求结束,进程内所有内存整块释放——**天然无泄漏**。
- Swoole/Hyperf 常驻模式:进程不退出,Java 的泄漏经验才适用(全局变量/闭包引用)。

### 4. 语言细节对照

| 特性 | Java | PHP |
|---|---|---|
| 变量 | `int x = 1;` | `$x = 1;`(所有变量带 $ 前缀) |
| 常量 | static final | `const MAX = 10;` / define() |
| 字符串插值 | 拼接/format | `"Hello, $name!"`(双引号内插值) |
| 数组 | 集合框架 | **array(list/map 三合一)** |
| 类 | class + 泛型 | class + trait(代码复用,≈ 组合) |
| 接口 | interface | interface(PHP 8 支持默认实现) |
| 枚举 | enum(5+) | **enum(PHP 8.1 引入)** |
| 命名空间 | package + import | namespace + use |
| main 入口 | public static void main | 脚本文件直接执行 |
| 强类型 | 编译期 | strict_types 声明(8.0+) |

### 5. PHP 8 的现代化(对 Java 开发者的好消息)

- JIT(8.0):CPU 密集场景性能大幅提升。
- 构造器属性提升(8.0):`public function __construct(public string $name) {}` ≈ Java record 风格。
- enum(8.1)、readonly 类(8.2)、typed 属性齐全——现代 PHP 与 Java 的语法代差在缩小。

## 小结

PHP 对 Java 开发者的核心冲击:**没有常驻应用**。一切状态(连接、缓存、static)要么外部化,要么每次重建。理解这个模型,就理解了 PHP 的部署简单性(无守护、无调优)与架构局限(高并发需外部设施或 Swoole)。
