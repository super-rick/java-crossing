# PHP · 08 部署运维

> 锚点:Java 的 JAR + JRE 镜像 + JVM 调优对应 PHP 的源码 + php-fpm 镜像 + pm.max_children 调优。
>
> 验证环境:纯文档(部署实践);版本基线 PHP 8.4 + nginx。

**一句话:PHP 部署最简——源码即产物,nginx + php-fpm 两个组件,调优核心是 FPM 进程池参数;没有「应用启动/守护」概念。**

## 部署形态对照表

| 维度 | Java | PHP |
|---|---|---|
| 构建产物 | JAR/WAR | **源码**(无编译,composer install 即完成依赖) |
| 典型镜像 | temurin JRE + JAR(200-400MB) | php:8.4-fpm + nginx(400-700MB) |
| 启动时间 | 5-30s | **毫秒级**(请求即执行) |
| 进程模型 | 1 JVM 多线程 | **FPM 进程池 + nginx** |
| 守护进程 | systemd/supervisor | **FPM master 自带**(无应用守护概念) |
| 调优 | -Xmx/-XX:GC | **pm.max_children**(核心)+ memory_limit |
| 优雅重启 | 需设计 | `php-fpm reload` / `nginx reload`(秒级) |
| 水平扩展 | 无状态 + 外部会话 | 同左(天然无状态) |

## 部署架构

```
客户端 → nginx(静态资源直接返回 + 动态转发) → php-fpm:9000 → 应用源码
```

- nginx 负责:静态文件、负载均衡、HTTPS 终止、缓存头。
- php-fpm 负责:执行 PHP 脚本(进程池)。
- 两个进程组分离:静态资源零 PHP 开销(比 Java 的静态资源经应用服务器更省)。

## FPM 核心调优(≈ JVM 参数的对位)

```
[www]
pm = dynamic                  # 动态进程管理(≈ 线程池自适应)
pm.max_children = 50          # 最大进程数(≈ 线程池 max)
pm.start_servers = 10
pm.min_spare_servers = 5
pm.max_spare_servers = 20
pm.max_requests = 500         # 每进程处理 N 请求后回收(防内存碎片)
```

- **pm.max_children 公式**:`可用内存(MB) ÷ 单进程峰值内存(MB)`。
- 例:8GB 服务器,单进程峰值 ~100MB → max_children ≈ 60-70(留系统余量)。
- `pm.max_requests`:防长驻进程内存缓慢增长(≈ 防泄漏的兜底手段)。

> ⚠️ Java 思维陷阱 1:按 JVM 堆调优思维——PHP 没有 -Xmx;内存上限是 `memory_limit`(单请求),进程数受系统内存约束。OOM 排查 = 看 FPM 日志 + 降低 max_children。
>
> ⚠️ Java 思维陷阱 2:找「应用守护/优雅停机」——FPM 自带进程管理,`php-fpm reload` 秒级生效(≈ 无停机发布);没有 Java 的启动预热/停机钩子。
>
> ⚠️ Java 思维陷阱 3:进程数当并发数用——max_children=50 意味着**同时只能处理 50 个请求**,第 51 个排队(502 超时);高并发要么加机器,要么 Swoole/Hyperf。

## 容器化

```dockerfile
# 双容器:php-fpm + nginx(compose 编排)
FROM php:8.4-fpm
WORKDIR /app
COPY composer.json composer.lock ./
RUN composer install --no-dev --optimize-autoloader
COPY . .
# PHP 扩展:docker-php-ext-install pdo_mysql opcache

# nginx 容器:静态资源 + 转发到 php-fpm:9000
```

LNMP 一键脚本/宝塔面板是传统部署主流;容器化同样成熟(php-fpm 官方镜像)。

## OPcache(性能关键,≈ JIT 预热)

```ini
opcache.enable=1
opcache.memory_consumption=128
opcache.max_accelerated_files=10000
```

- 缓存编译后的字节码(≈ JVM 的预热效果);**生产必开**,不开性能差 3-5 倍。
- 发布代码后需 `opcache_reset()` 或 reload(缓存失效策略)。

## CI/CD 流水线

```yaml
- run: composer install --no-dev
- run: vendor/bin/phpunit
- run: php -l 语法检查(src 下所有文件)
- run: docker build -t registry/app:$TAG .
- run: docker push registry/app:$TAG
```
