# Node.js · 09 监控

> 锚点:Java 的 Actuator + Micrometer + JFR 对应 Node 的 prom-client + pino + --inspect/--trace-gc。
>
> 验证环境:纯文档;版本基线 prom-client 15.x。

**一句话:Node 监控同样「自己接」——prom-client 暴露 /metrics,pino 结构化日志,`--trace-gc` 看 GC,clinic 火焰图分析性能;链路追踪统一 OpenTelemetry。**

## 监控对照表

| 维度 | Java | Node.js |
|---|---|---|
| 指标暴露 | Actuator(自动) | **prom-client**(手动注册 /metrics) |
| 运行时指标 | JVM 内存/GC/线程 | process.memoryUsage() / prom-client 默认指标 |
| 健康检查 | /actuator/health | 自建 /healthz |
| 日志 | SLF4J + Logback | **pino**(高性能 JSON)/ winston |
| 性能剖析 | JFR / jstack / MAT | **clinic.js** / node --inspect + DevTools |
| GC 观察 | GC 日志 | `--trace-gc` / `--trace-gc-verbose` |
| 内存快照 | MAT / jmap | **--heapsnapshot**(Chrome DevTools 分析) |
| 链路追踪 | OTel / SkyWalking | OpenTelemetry JS SDK |

## 指标接入(最小 Prometheus,Express 示例)

```js
const client = require("prom-client");
const express = require("express");

const ordersCounter = new client.Counter({ name: "orders_total", help: "创建的订单总数" });

const app = express();
app.get("/metrics", async (req, res) => {
  res.set("Content-Type", client.register.contentType);
  res.end(await client.register.metrics());
});

app.post("/orders", (req, res) => {
  ordersCounter.inc();  // ≈ Micrometer Counter
  res.json({ ok: true });
});
```

- `prom-client` 默认收集 Node 运行时指标(事件循环延迟/堆内存/句柄数)。
- Grafana + Prometheus 采集规则与 Java/Go/Python 服务一致(跨语言统一栈)。

## 日志规范(pino)

```js
const pino = require("pino");
const logger = pino();  // 默认输出 JSON 行(≈ Logback JSON encoder)

logger.info({ orderId: 1001 }, "order created");  // 结构化字段,≈ SLF4J 占位符
// 输出: {"level":30,"time":...,"msg":"order created","orderId":1001}
```

- 统一 stdout + 采集器(Loki/ELK),别写文件轮转——与 Java 管线一致。

## 性能剖析:clinic.js(≈ JFR 的易用版)

```bash
npm install -g clinic
clinic doctor -- node app.js    # 一键生成诊断报告(事件循环延迟/CPU/内存)
clinic flame -- node app.js     # 火焰图(≈ JFR CPU 采样)
```

- 事件循环延迟是 Node 特有核心指标:`process.hrtime` 采样或 prom-client 的 eventLoopLag。
- 线上轻量排查:`node --inspect` 远程调试(生产慎用)或 `clinic`。

> ⚠️ Java 思维陷阱 1:等框架送监控——Node 无 Actuator,/metrics 与 /healthz 自己写(各 5-10 行)。
>
> ⚠️ Java 思维陷阱 2:JFR/jstack 思维——Node 的对应物:火焰图(clinic)、堆快照(--heapsnapshot)、事件循环延迟监控;没有「线程 dump」概念(单线程)。
>
> ⚠️ Java 思维陷阱 3:不监控事件循环延迟——这是 Node 的「血压计」:延迟飙高 = 事件循环被阻塞(同步代码/CPU 密集),比 CPU 使用率更早报警。

## 统一监控栈建议

```
Node 应用 → /metrics(prom-client)+ JSON 日志(stdout)+ OTel
        ↓
   Prometheus / Loki / Jaeger(Tempo)
        ↓
     Grafana 统一面板
```
