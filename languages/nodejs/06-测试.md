# Node.js · 06 测试

> 锚点:Java 的 JUnit 5 + Mockito + JaCoCo 对应 Node 的 Jest/Vitest + jest.mock/vi.mock + coverage。
>
> 验证环境:Node 22.23.0(实测 node:test 输出;Jest 为生产主流)。

**一句话:Jest 是事实标准(断言 + mock + 覆盖率 + watch 全家桶);Node 22 内置 node:test 零依赖可用;Node 测试的独特之处是「几乎全是异步测试」。**

## 测试对照表

| 维度 | Java | Node.js |
|---|---|---|
| 框架 | JUnit 5 | **Jest** / Vitest / node:test(内置) |
| 测试发现 | @Test + 扫描 | `*.test.js` / `*.spec.js` 约定 |
| 断言 | Assertions.* | `expect(x).toBe(y)`(Jest)/ assert(node:test) |
| 参数化 | @ParameterizedTest | `test.each([...])`(Jest) |
| 生命周期 | @BeforeEach/@AfterEach | beforeEach / afterEach / beforeAll |
| Mock | Mockito | **jest.mock / jest.spyOn**(模块级替换) |
| 覆盖率 | JaCoCo | `--coverage`(Jest 内置) |
| 异步测试 | 同步为主 | **async 测试函数 + await(默认)** |
| 超时 | (JUnit 默认长) | Jest 默认 5s |

## 完整对照示例(实测,node:test 零依赖)

被测代码 `calc.js`:

```js
function add(a, b) {
  return a + b;
}

function divide(a, b) {
  if (b === 0) throw new Error("division by zero");
  return a / b;
}

module.exports = { add, divide };
```

测试代码 `calc.test.js`:

```js
const { test } = require("node:test");
const assert = require("node:assert/strict");
const { add, divide } = require("./calc");

// 参数化:node:test 无 test.each(Jest 专属),用循环生成测试
for (const [a, b, expected] of [
  [1, 2, 3],
  [0, 0, 0],
  [-1, 1, 0],
]) {
  test(`add(${a}, ${b}) = ${expected}`, () => {
    assert.equal(add(a, b), expected);
  });
}

test("divide normal", () => {
  assert.equal(divide(10, 2), 5);
});

test("divide zero throws", () => {
  assert.throws(() => divide(1, 0), /division by zero/);
});
```

运行:`node --test calc.test.js`
实测输出:

```
# tests 5
# pass 5
# fail 0
```

## 关键差异

### 1. 异步测试是常态

```js
// Jest:异步测试直接 async + await
test("fetch order", async () => {
  const order = await fetchOrder(1);
  expect(order.id).toBe(1);
});

// ❌ 忘 return/await:测试立即通过(假绿)
test("bad async", () => {
  fetchOrder(1).then((o) => expect(o.id).toBe(2)); // 永不失败!
});
```

- Java 测试几乎同步;Node 的 IO 全异步,**每个测试几乎都是 async 的**——忘 await 是最隐蔽的假绿来源。

### 2. mock 是模块级的(比 Mockito 更「整体」)

```js
// Jest:替换整个模块(≈ Mockito mock 一个类)
jest.mock("./payment", () => ({
  charge: jest.fn().mockResolvedValue({ ok: true }),
}));
```

- Mockito mock 类的方法;Jest mock **整个模块导出**,粒度更粗但更简单。

### 3. supertest ≈ MockMvc(HTTP 层测试)

```js
const request = require("supertest");
const app = require("../app");

test("POST /orders 201", async () => {
  const res = await request(app).post("/orders").send({ item: "coffee", quantity: 2 });
  expect(res.status).toBe(201);
});
```

### 4. 覆盖率门槛

```bash
npx jest --coverage --coverageThreshold='{"global":{"lines":80}}'
```

> ⚠️ Java 思维陷阱 1:测试不写异步处理——每个涉及 IO 的测试都 async + await,否则假绿。
>
> ⚠️ Java 思维陷阱 2:找 @Test 注解——Jest 靠文件命名(`.test.js`)+ 顶层 test() 函数,无注解体系。
>
> ⚠️ Java 思维陷阱 3:Mockito 式「mock 具体类」——Jest mock 模块导出;jest.spyOn 可 mock 对象方法,但「模块工厂」是主力。
