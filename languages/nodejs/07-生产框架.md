# Node.js · 07 生产框架

> 锚点:Java 的 Spring Boot + MyBatis + Bean Validation 对应 Node 的 Express/Fastify/NestJS + Prisma/TypeORM + zod。
>
> 验证环境:Node 22.23.0;框架版本以官方稳定版为准(2026-08)。

**一句话:Node 框架分三派——Express 极简自由(≈ Go 组合文化)、Fastify 高性能(内置校验)、NestJS 结构化(≈ TypeScript 版 Spring Boot,Java 开发者最亲切)。**

## 框架对照表

| 维度 | Java | Express | Fastify | NestJS |
|---|---|---|---|---|
| 定位 | 全家桶 | 极简(占 70%+ 生态) | 高性能 API | 企业结构化 |
| 依赖注入 | Spring 容器 | 无(手动) | 无(插件体系) | **内置 DI(≈ Spring)** |
| 路由 | @RequestMapping | 链式注册 | 链式 + 声明式 | @Controller 装饰器 |
| 中间件 | Filter/Interceptor | **中间件链**(核心) | 生命周期钩子 | 守卫/拦截器/管道 |
| 参数校验 | Bean Validation | 手动 | **内置 JSON Schema** | class-validator + DTO |
| TS 支持 | — | 弱(JS 为主) | 好 | **TS 原生(必须 TS)** |
| 迁移成本(Java 视角) | —(已知) | 中(概念差异大) | 中 | **低(最像 Spring)** |

## 最小 Fastify 服务(生产推荐)

```js
const Fastify = require("fastify");

const app = Fastify({ logger: true });

app.get("/hello", async (req, reply) => {
  const { name = "world" } = req.query;
  return { message: `Hello, ${name}` };   // 自动 JSON 序列化
});

app.listen({ port: 8080 });
```

- Fastify 自带 JSON Schema 校验与序列化优化(性能 ≈ 手写 JSON 的水平)。
- 对应关系:`app.get(path, handler)` ≈ `@GetMapping`;handler 返回对象自动转 JSON(≈ @ResponseBody)。

## 生产选型建议

| 场景 | 选择 |
|---|---|
| 快速原型/小服务/生态兼容 | **Express**(资料最多) |
| 高吞吐 API(性能敏感) | **Fastify** |
| 企业级/团队规范/TS | **NestJS**(最像 Spring Boot) |
| BFF 层 | Express/Fastify + TS |

### NestJS ≈ Spring Boot 对照

```ts
// ≈ @RestController + @Service + @Autowired
@Controller("orders")                       // ≈ @RestController
export class OrdersController {
  constructor(private readonly ordersService: OrdersService) {}  // ≈ 构造注入

  @Get(":id")                               // ≈ @GetMapping("/{id}")
  getOrder(@Param("id") id: number) {       // ≈ @PathVariable
    return this.ordersService.find(id);
  }
}
```

Java 开发者看 NestJS 的装饰器 + DI + DTO 体系几乎零门槛——它本质就是「TS 化的 Spring」。

## ORM 对照表

| 维度 | Java | Node.js |
|---|---|---|
| 全功能 ORM | JPA/Hibernate | **Prisma**(类型安全,自动迁移)/ TypeORM |
| 查询构建器 | MyBatis(手写 SQL) | knex / Sequelize |
| 自动迁移 | Flyway/Liquibase | Prisma Migrate / TypeORM migration |
| 校验 | Bean Validation | **zod**(schema 校验,TS 生态标配) |

### zod ≈ Bean Validation(TS 生态标配)

```ts
import { z } from "zod";

const CreateOrderSchema = z.object({
  item: z.string().min(1),
  quantity: z.number().int().positive(),
});

const parsed = CreateOrderSchema.parse(req.body);  // 校验失败自动抛错
```

## 微服务生态对应

| 需求 | Java | Node.js |
|---|---|---|
| RPC | gRPC/Dubbo | gRPC(@grpc/grpc-js)/ tRPC(全栈) |
| 消息 | Kafka 客户端 | kafkajs / amqplib |
| 缓存 | Redis 客户端 | ioredis |
| 任务调度 | XXL-Job/Quartz | node-cron / BullMQ |
| 网关 | Spring Cloud Gateway | K8s Ingress / Express 网关 |

> ⚠️ Java 思维陷阱 1:在 Express 里找 Spring 的「全家桶」——Express 只有路由 + 中间件,ORM/校验/日志全要自己组合(与 Go 的组合文化同);要全家桶体验直接选 NestJS。
>
> ⚠️ Java 思维陷阱 2:同步思维写 handler——Express 4 的 handler 不原生支持 async 错误捕获,async handler 抛错要包装(Express 5/Fastify 已修复);Fastify/NestJS 原生 async,推荐。
>
> ⚠️ Java 思维陷阱 3:忽略 JSON Schema/校验——Node 无 Bean Validation 默认;Fastify schema 或 zod 是生产必配,裸手写校验是反模式。
