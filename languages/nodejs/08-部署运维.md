# Node.js · 08 部署运维

> 锚点:Java 的 JAR + JRE 镜像 + JVM 调优对应 Node 的 node 镜像 + pm2/systemd + V8 内存参数。
>
> 验证环境:纯文档(部署实践);版本基线 Node 22 LTS。

**一句话:Node 部署 = node 镜像 + 依赖(node_modules)+ 进程守护;单进程扛不住多核——**集群(cluster)或多实例才是水平扩展的正解。

## 部署形态对照表

| 维度 | Java | Node.js |
|---|---|---|
| 构建产物 | JAR/WAR | 源码 + node_modules(或打包 bundle) |
| 典型镜像 | temurin JRE + JAR(200-400MB) | node:22-alpine + 依赖(300-500MB) |
| 启动时间 | 5-30s | 0.5-2s |
| 进程模型 | 1 JVM 多线程 | **单进程单线程 + cluster 多实例** |
| 调优 | -Xmx/-XX:GC | `--max-old-space-size`(V8 堆上限) |
| 进程守护 | systemd/supervisor | **pm2** / systemd / K8s |
| 优雅停机 | shutdown hook | SIGTERM + server.close() |

## 生产部署流程

### 1. 依赖锁定

```bash
npm install          # 本地安装
npm ci               # CI/生产:按 package-lock.json 精确安装(≈ 版本钉死)
```

- `package-lock.json` 必须提交(≈ 提交 pom 锁定版本);CI 用 `npm ci` 而非 `npm install`。

### 2. 进程管理:pm2(≈ supervisor + 集群)

```bash
npm install -g pm2
pm2 start app.js -i max        # 集群模式:多核全用(≈ JVM 线程池的进程版)
pm2 restart app --update-env   # 环境变量变更后重启
pm2 logs app                   # 集中日志
```

- `-i max` = 每个 CPU 核一个进程(利用多核)。
- 心智转换:JVM 一个进程内多线程 → Node **多进程实例 + 负载均衡**(cluster 内置于 pm2/K8s 多副本)。

### 3. 容器化

```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --omit=dev          # 只装生产依赖(≈ 不打包测试依赖)
COPY . .
ENV NODE_ENV=production
EXPOSE 8080
CMD ["node", "app.js"]
```

> ⚠️ Java 思维陷阱 1:多线程假设——Node 单进程只用一个核,部署必须多实例(pm2 -i max 或 K8s 多副本);**单实例 + 高并发 = CPU 单核瓶颈**。
>
> ⚠️ Java 思维陷阱 2:JVM 调优参数——V8 只有 `--max-old-space-size=512`(堆上限,≈ -Xmx)与 `--max-semi-space-size`;默认堆上限约 2GB(64 位),容器内存限制记得同步设置。
>
> ⚠️ Java 思维陷阱 3:忘记 npm ci——生产用 npm install 会因版本范围浮动装出不同依赖;必须 npm ci(lock 精确)。
>
> ⚠️ Java 思维陷阱 4:内存泄漏——V8 GC 与 JVM 类似,但 Node 的常见泄漏源是「未清理的监听器/定时器/闭包引用」;用 `--heapsnapshot` + Chrome DevTools 分析(≈ MAT)。

## 水平扩展架构(多实例共享状态)

```
                 ┌── Node 实例 1 ──┐
LB/Ingress ──────┼── Node 实例 2 ──┼── Redis(会话/缓存/锁)
                 └── Node 实例 3 ──┘
```

- 多实例后:**进程内内存不再是可靠状态**——session/缓存/锁必须外部化(Redis),与 Java 多实例部署同理。
- 本仓库示例(nodejs-order-service)的内存 store 在单实例场景演示;生产要换成 Redis/DB(见 README 说明)。

## 健康检查与优雅停机

```js
const server = app.listen(8080);

process.on("SIGTERM", () => {          // ≈ shutdown hook
  console.log("shutting down...");
  server.close(() => process.exit(0)); // 等在途请求完成
  setTimeout(() => process.exit(1), 10000).unref();
});
```

## CI/CD 流水线(Node 服务)

```yaml
- run: npm ci
- run: npm test
- run: npm run build   # TS 项目:编译(≈ javac)
- run: docker build -t registry/app:$TAG .
- run: docker push registry/app:$TAG
```
